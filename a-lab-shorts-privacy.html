Официальная информация A-LAB Shorts

Дата вступления в силу: 19 ноября 2026 года · Последнее обновление: 19 ноября 2026 года

Коротко: A-LAB Shorts предназначен для обработки разрешённых клипов и загрузки коротких видео в личный YouTube-канал. Google-доступ используется для проверки выбранного канала и загрузки новых роликов со статусом Private. Мы не продаём данные Google и не используем их для рекламы.

1. Кто обрабатывает данные

Оператор приложения — A-LAB, независимый разработчик внутреннего инструмента A-LAB Shorts. Контакт по вопросам конфиденциальности и удаления данных: edanovanton@gmail.com. Описание продукта: A-LAB Shorts.

Это инструмент с ограниченным доступом, предназначенный для владельца авторизованного YouTube-канала. На информационных страницах нет регистрационной формы и не запрашиваются пароли Google.

2. Какие данные запрашиваются и для чего

Google / YouTube

  • Разрешение youtube.readonly — получение идентификатора YouTube-канала, его названия и технических сведений, необходимых для проверки, что OAuth-доступ предоставлен нужному каналу. Приложение не использует его для сбора личных видео других пользователей.
  • Разрешение youtube.upload — передача подготовленного MP4 и пользовательских метаданных (название, описание, категория и теги) в собственный канал YouTube после явного решения владельца. Автоматическая загрузка в предусмотренном конвейере выполняется только со статусом Private.
  • OAuth-реквизиты — идентификатор клиента, секрет клиента, токен обновления (refresh token) и ожидаемый ID канала. Они используются для безопасного обращения к YouTube API. Мы не запрашиваем пароль Google и не храним его.
  • Результат операции — ID загруженного видео, ссылка и статус закрытого доступа; используется для проверки результата и предотвращения повторной загрузки.

Доступ не запрашивается к Gmail, Google Drive, контактам, сообщениям или истории поиска. Данные Google применяются исключительно для указанных функций. Разрешения Google выдаются пользователем в официальном окне OAuth и могут быть отозваны.

Исходные видео и метаданные

Если владелец добавляет ссылку на разрешённый Twitch-клип, сервис получает адрес исходника, имя стримера, его краткое описание, подтверждение наличия прав и выбранные параметры монтажа. Эти данные не извлекаются из Google-аккаунта. При рендеринге временно обрабатываются исходное видео и оригинальная звуковая дорожка.

3. Использование данных

  • Проверить ID и название авторизованного YouTube-канала до любой загрузки.
  • Подготовить короткое вертикальное видео с оригинальным звуком и сформировать метаданные.
  • Загрузить видео как закрытый черновик исключительно по запросу владельца канала.
  • Показать результат операции, диагностировать технические ошибки и предотвратить случайные дубли.

Мы не передаём данные Google рекламодателям и брокерам данных, не продаём их, не используем для персонализированной рекламы, кредитного скоринга или обучения моделей ИИ. Использование, хранение и допустимая передача данных Google соответствуют Google API Services User Data Policy, включая требования Limited Use.

4. Кому передаются данные

  • Google / YouTube: OAuth-процедура, проверка канала и загрузка пользовательского видео по официальному YouTube Data API.
  • GitHub Actions: выполнение задач облачного монтажа и загрузки. Секреты GitHub Actions предоставляются процессам только при выполнении соответствующих задач. GitHub обрабатывает технические данные в соответствии со своими условиями и политикой конфиденциальности.
  • Twitch: исходные видео скачиваются по выбранным пользователем ссылкам для монтажа при наличии разрешения правообладателя; приложение не передаёт токены Google сервису Twitch.

Сторонние сервисы не получают независимого права использовать данные Google для своих рекламных или иных целей. Передача ограничивается техническими задачами приложения, выбранными и разрешёнными владельцем канала, либо обязательными законными требованиями.

5. Хранение и сроки

  • OAuth refresh token и клиентские реквизиты — в закрытых GitHub Actions Repository secrets до отзыва согласия или удаления владельцем репозитория. Они не публикуются в коде сайта и не предназначены для открытых журналов.
  • Исходные клипы на сервере рендера — временные файлы одноразового задания GitHub Actions, удаляемые после завершения и освобождения временного окружения.
  • Готовый MP4 и JSON-метаданные — закрытый GitHub Actions Artifact со сроком хранения, установленным в текущем конвейере, **3 дня**.
  • Квитанция загрузки (ID, ссылка, статус) — закрытый GitHub Actions Artifact, **14 дней**. Данные о выполнении рабочих процессов и технические журналы могут храниться дольше в соответствии с политиками и настройками GitHub.
  • Загруженное видео в YouTube — хранится в аккаунте YouTube до изменения или удаления владельцем канала, согласно правилам YouTube.

Если настройки GitHub или функции сервиса изменятся, политика будет обновлена. Владелец может досрочно удалить артефакты, результаты и секреты в настройках соответствующих сервисов.

6. Безопасность

Рабочий репозиторий A-LAB Shorts является закрытым. Для выдачи разрешений используется стандартный OAuth Google; доступ к видео и идентификации канала ограничен согласованными областями доступа. Загрузка публикуемого ролика и публичная доступность — разные действия: конвейер не выполняет автоматическую публичную публикацию. Ни один технический способ защиты не исключает все риски, поэтому рекомендуем периодически проверять активные подключения Google и GitHub.

7. Как отозвать доступ и запросить удаление

  1. Перейдите в настройки подключённых приложений Google и отмените доступ A-LAB Shorts (название отображается согласно настройкам экрана согласия).
  2. Владельцу репозитория GitHub следует удалить значения YOUTUBE_CLIENT_ID, YOUTUBE_CLIENT_SECRET, YOUTUBE_REFRESH_TOKEN и YOUTUBE_EXPECTED_CHANNEL_ID в настройках Actions Secrets; при необходимости удалить Actions Artifacts.
  3. Для запроса сведений об обработке данных, прекращения обработки и удаления доступных оператору сохранённых данных отправьте письмо на edanovanton@gmail.com. В письме опишите запрос и данные, которые нужно удалить, без паролей и токенов.

Отзыв OAuth-доступа прекращает будущие авторизованные обращения приложения к YouTube. Уже загруженные ролики необходимо удалять отдельно в YouTube Studio, если владелец хочет удалить и их.

8. Эти публичные страницы

Страницы описания приложения и этой политики — статические. Мы не размещаем на них собственные аналитические скрипты, рекламные пиксели и формы сбора персональных данных. При посещении GitHub Pages хостинг-провайдер может обрабатывать стандартные технические журналы запросов согласно собственной политике.

9. Обновления политики

Политика может меняться при изменении функциональности, используемых API или способов хранения. Актуальная редакция всегда размещается по адресу https://antosssha.github.io/a-lab-shorts-privacy.html. При существенном изменении использования данных Google до начала нового способа обработки будет запрошено необходимое согласие.

English privacy summary

How we handle YouTube account data.

Operator: A-LAB, contact edanovanton@gmail.com. Purpose: privately prepare and upload user-authorized short videos to the owner's YouTube channel. Scopes: youtube.readonly to verify the authenticated channel ID/title, and youtube.upload to upload approved MP4 files as private videos. We do not request Gmail, Drive, contacts or passwords.

Storage and sharing: OAuth credentials are stored as encrypted GitHub Actions repository secrets until removed or revoked; Google/YouTube receives only authorized API requests and uploads. GitHub Actions runs temporary processing jobs; output video artifacts are retained for 3 days, upload receipts for 14 days, and workflow logs according to GitHub's retention settings. No Google user data is sold, used in advertising or for AI model training. Google API data use adheres to the Google API Services User Data Policy including Limited Use.

Control and deletion: revoke app authorization at Google Account connections; repository owners may delete GitHub secrets and artifacts. Contact edanovanton@gmail.com for access or deletion requests. YouTube uploads remain under the channel owner's control and must be separately deleted in YouTube Studio if desired.
